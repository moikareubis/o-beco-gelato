# HUB Beco Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the HUB Beco — a git-versioned set of markdown files that gives Claude memory and per-area playbooks for advising on the Beco Gelato business, without duplicating the Complexo Beco dashboard or the Balanceador.

**Architecture:** Mostly content, no application code, plus one small addition to the existing Complexo Beco artifact. A small always-read `hub/INDEX.md` routes a request to 1–2 `hub/areas/*.md` playbooks and the `hub/memoria/*.md` files they declare as dependencies; `hub/log/` is append-only and read only on demand. Every log entry is also written to the Complexo Beco artifact's own database (collection `hub_log`), which a new 11th tab, "Painel do HUB", renders — so decisions and progress stay visible in the browser, not just in chat history. The existing dashboard source folder is renamed from `cerebro/` to `complexo/` to free the name, and `README.md`/`AGENTS.md` are updated to match.

**Tech Stack:** Markdown files in the `o-beco-gelato` git repo. No build, no runtime.

**Spec:** [docs/superpowers/specs/2026-11-03-hub-beco-design.md](../specs/2026-11-03-hub-beco-design.md)

## Global Constraints

- Repo root: `/Users/gabrielsampaio/Claude/Projects/O Beco Gelato`. Work in Portuguese (per `AGENTS.md`).
- The HUB never proposes recipes/formulation or reopens bancada decisions — regra herdada do `AGENTS.md` atual.
- `memoria/*.md` holds only stable, decided facts (prices, lines, rules, targets) — never the day's stock/cash numbers; those stay in Complexo Beco.
- `hub/log/*.md` is append-only: a step that would rewrite an existing entry is wrong.
- Every `areas/*.md` follows the 5-part template from the spec: recebe / depende de memória / cruza com / nunca faz / formato de saída.
- `hub/INDEX.md` must be small enough that reading it alone is cheap (target: under 60 lines).
- After the rename, no file in the repo may still reference `cerebro/` as the dashboard's path.

## Review Focus

- **Stale memory:** a `memoria/*.md` file is read as if it were live stock/cash data. Task 3 pins this with an explicit non-negotiable header in every memory file.
- **Isolated wrong recommendation:** an `areas/*.md` file that should cross-reference another area (per spec, `eventos.md` always crosses with `financeiro.md` and `produtos.md`) is missing that reference. Task 4 verifies every "cruza com" section against the spec's declared crossings.
- **Log overwritten instead of appended:** nothing enforces append-only in plain markdown. Task 5 adds an explicit instruction line inside the log file itself and verifies the file still contains the original stub entry after a second write.
- **Stray old path after rename:** `README.md`, `AGENTS.md`, or any other file keeps citing `cerebro/` as the dashboard source after Task 1 renames it. Task 1 greps the whole repo for the literal string after the rename.
- **Pendencias duplicating the Painel tab:** `memoria/pendencias.md` ends up listing day-to-day operational pendências that already live in the Complexo Beco Painel. Task 3 pins the scope rule in the file's own header.
- **Markdown log and artifact `hub_log` drifting apart:** a decision gets written to one store but not the other, so the Painel do HUB tab shows a different history than `hub/log/*.md`. Task 7 verifies a written entry appears in both.

**Interfaces:**

- Produces: 8 filenames `hub/INDEX.md` (Task 2) already lists.

- [ ] **Step 1: Write each file against the fixed 5-part template**

Every file gets exactly these 5 headings, in this order: `## O que recebe`, `## Depende de` (list exact `memoria/*.md` filenames, never "toda a memória"), `## Cruza com` (list exact `areas/*.md` filenames, or "nenhuma por padrão"), `## Nunca faz`, `## Formato de saída` (fixed to: situação → oportunidade e por quê → prioridade → próximos passos com prazo → o que falta saber → pendência — copy this line verbatim into every file). Per-file content:

- `eventos.md`: recebe convites/propostas de evento; depende de `produtos.md` + `financeiro.md`; cruza com `comercial-b2b.md` (quando o evento é também porta de entrada comercial) e `portfolio.md` (quando decide qual sabor levar); nunca decide sozinho sem cruzar financeiro e produtos primeiro (per spec).
- `comercial-b2b.md`: recebe propostas/negociação com ponto de venda ou parceiro; depende de `produtos.md` + `decisoes.md`; cruza com `expansao.md` (quando a negociação é sobre abrir ponto novo) e `financeiro-unit.md`.
- `expansao.md`: recebe critério de onde abrir ponto novo; depende de `produtos.md` + `financeiro.md`; cruza com `comercial-b2b.md` e `financeiro-unit.md`; nunca decide expansão sem olhar margem por canal.
- `marketing.md`: recebe conteúdo/campanha/referência de marca; depende de `produtos.md` + `decisoes.md` (regra de escrita e trava de claims); cruza com `trafego.md`.
- `trafego.md`: recebe decisão de investimento/teste de anúncio; depende de `financeiro.md`; cruza com `marketing.md` (nunca decide investimento sem o contexto de campanha do marketing).
- `loja.md`: recebe pergunta de execução no ponto de venda (apresentação, abordagem, ação promocional); depende de `produtos.md`; cruza com `comercial-b2b.md` quando a ação é num ponto parceiro.
- `portfolio.md`: recebe decisão de sabor/linha (lançar, descontinuar, reposicionar preço); depende de `produtos.md` + `decisoes.md` (regra das 3 linhas, lançamento roda sozinho); cruza com `financeiro-unit.md`.
- `financeiro-unit.md`: recebe pergunta de margem por canal/ponto; depende de `financeiro.md` + `produtos.md`; cruza com nenhuma por padrão (é consultada por outras, raramente inicia).
